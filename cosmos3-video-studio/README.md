# Cosmos 3 Nano World Model Studio

Generate videos with [NVIDIA Cosmos3-Nano](https://huggingface.co/nvidia/Cosmos3-Nano), the open Cosmos 3 world model for physical AI, on your own GPU. [vLLM-Omni](https://github.com/vllm-project/vllm-omni) serves the model, and a small Gradio studio gives you text-to-video and image-to-video in the browser. Use it to prototype scenes and synthetic data clips for robotics and autonomous systems.

Built on NVIDIA Cosmos.

Current versions: vLLM-Omni `vllm/vllm-omni:cosmos3` (pinned by digest, 2026-10-19 build), nvidia/Cosmos3-Nano revision `45666784803b3a7ad577e0def405f9afcc3bddb2`, Gradio 6.32.0, Python 3.12.16.

The studio listens on port 7860 and opens from the **open-cosmos-studio** link. The vLLM-Omni API is bound to the instance itself (127.0.0.1:8000) and is not exposed publicly.

## Before you deploy: Hugging Face access

Cosmos guardrails are on by default. They use the gated [nvidia/Cosmos-1.0-Guardrail](https://huggingface.co/nvidia/Cosmos-1.0-Guardrail) model.

1. Before you deploy, sign in to Hugging Face, open https://huggingface.co/nvidia/Cosmos-1.0-Guardrail and accept its access conditions. Access is granted immediately.
2. Then create a read token for the same account and enter it as `HF_TOKEN`. On the deploy page you can choose "Use a secret" to bind a saved secret, or paste the token.

The token is needed only for this guardrail model; Cosmos3-Nano itself is not gated.

Never put a token anywhere except this parameter. The server runs with Cosmos guardrails enabled, and the studio never turns them off; keep them on in your own API requests.

## Hardware

- Default instance: one NVIDIA L40S 48GB, with 200 GiB of disk for the container images, the model and the guardrail models, a large download (tens of GB) on first start.
- The upstream vLLM recipe lists one H200, H100 or A100 as the single-GPU profile. For longer or larger clips, deploy on an A100 80GB.
- The studio defaults to 1280x720, 45 frames (about 2 seconds at 24 fps) and 30 steps. Raise frames and steps only with GPU memory to spare.

## Use it

1. Deploy and wait until the instance is Running.
2. Open the **open-cosmos-studio** link. The first start downloads the model and the guardrail models; the status line reads "ready" when Cosmos3-Nano is loaded. Press "Refresh status" to check.
3. **Text to video**: write a prompt, pick resolution, frames, steps and seed, and press Generate.
4. **Image to video**: upload a first frame (JPG, PNG or WebP), describe the motion, and press Generate.

Each clip is an MP4 with audio generated by the model. Generation runs one request at a time.

To call the API from your own machine, forward the port with the Brev CLI:

```
brev port-forward INSTANCE_NAME --port 8000:8000
curl -X POST http://localhost:8000/v1/videos/sync -H "Accept: video/mp4" \
  -F "prompt=A forklift moves a pallet across a warehouse floor" \
  -F "size=1280x720" -F "num_frames=45" -F "fps=24" \
  -F "num_inference_steps=30" -F "seed=123" --output out.mp4
```

Add `-F "input_reference=@frame.png"` for image-to-video.

## How data persists

Everything lives under `/home/ubuntu/workspace/cosmos3-studio` on the instance:

- Model cache (Hugging Face): `/home/ubuntu/workspace/cosmos3-studio/huggingface`
- Generated videos: `/home/ubuntu/workspace/cosmos3-studio/outputs`
- Studio Python environment: `/home/ubuntu/workspace/cosmos3-studio/envs`

They survive a stop and start of the instance. They are removed when the instance is deleted, so download the videos you want to keep.

## Stop or delete to control cost

- **Stop** the instance from the Brev console when you are not using it. The model cache and your videos are kept, and both containers start again on the next start (`restart: unless-stopped`). Storage is still billed while the instance is stopped.
- **Delete** the instance when you are finished. This removes the instance and all of its data, including downloaded models and generated videos.
